# ADR 0002：模组扫描与静态兼容性检查

- 状态：已接受
- 日期：2026-11-15

## 背景

AGMP 只扫描文件夹模组，而用户的 mods 目录中全部是 zip；同时用户希望显示每个模组支持的游戏版本，并得到模组包内兼容性提示。

## 决策

1. 每次启动程序、以及每次创建/编辑/删除后，都重新扫描 mods 目录，不缓存。
2. 扫描 mods 目录顶层的：
   - `*.zip` 文件
   - 包含 `info.json` 的文件夹
3. **以 zip 内 `info.json` 为权威来源**，文件名只作兜底；兼容两种内部布局：
   - `Name_Version/info.json`
   - `Name/info.json`
4. 解析字段：`name`、`version`、`title`、`author`、`factorio_version`、`description`、`dependencies`。
5. 同一内部名存在多个版本时，选择最高版本，其余在扫描警告中列出。
6. 内置/DLC 模组（`base`、`elevated-rails`、`quality`、`recycler`、`space-age`）只列出，不可选为成员。
7. 模组包自身的 `factorio_version` 固定为 `2.1`。
8. 静态兼容性检查：
   - 选中模组的 `factorio_version` 不是 `2.1`：不可选，阻止生成
   - 依赖约束的版本接受 `x.y` 与 `x.y.z`；两段形式按 `x.y.0` 参与比较。此兼容只用于依赖约束，模组包自身版本仍必须三段
   - 依赖名称允许 ASCII 字母、数字、`-`、`_` 和内部空格，支持 `! Squeak Through` 等实际模组声明
   - 内置模组依赖成功解析后直接跳过，因此 `base >= 2.1` 不产生警告，也不需要启动游戏或读取实际游戏版本
   - 选中成员之间存在 `!` 声明冲突：阻止生成
   - 冲突目标已安装但未选中：警告并显示当前启用状态；未安装则不提示
   - 必需依赖缺失或版本不足：警告，允许继续（便于分享给已安装依赖的人）
   - 可选依赖存在但版本不满足：警告
   - 推荐依赖缺失：警告
   - 仍无法解析的依赖声明只警告，不参与后续依赖检查
9. 不自动补齐传递依赖。成员自身的 `info.json` 已声明依赖，Factorio 会自行解析；自动补齐会重复约束且不能解决“未安装”问题。
10. 不读取 `mod-settings.dat`，不修改成员模组；兼容检查不启动 Factorio，也不读取 `factorio-current.log`。

## 后果

- 扫描结果与游戏实际加载的元数据一致，不再受 zip/文件夹形式影响。
- 兼容性提示是静态的，无法发现运行时脚本或数据阶段的真实冲突。
- 用户选择不兼容模组时会被阻止；缺依赖时仍可生成，但在本机启用可能失败。
